IDOL — ORDERED DEVELOPMENT BACKLOG
==================================

Purpose: sequential development by Codex or Claude in the idol library.
Striplib import is the first task. Independent scientific validation is
managed exclusively in the separate idol-benchmark repository.
Repository: https://github.com/hlefebvr/idol

EXECUTION RULES
---------------
Read AGENTS.md, SKILLS.md and the relevant skills before each task.
Work in numerical order, one focused task at a time. Inspect the current
implementation first: an item may already be partially implemented.
[ ] = pending; [D] = design proposal / maintainer approval required;
[A] = audit first, not permission for a wholesale rewrite;
[+] = additional proposed task. All tasks are initially pending.
For [D], deliver a concrete proposal with public API examples, alternatives,
mathematical invariants, migration impact and tests. Wait for approval before
implementation. If blocked, record why; ask whether to proceed to independent
items. Never silently skip prerequisites or change public APIs/defaults.
Use small, explicit, pseudocode-like implementations; comments only where
needed. Prefer incremental updates, partial invalidation, then lazy rebuild.
Do not sacrifice clarity without significant measured performance benefit.

For every task: reproduce the issue or establish a baseline, implement the
smallest coherent change, add tests, run relevant available tests, document
limitations and report the commit/revision, commands and actual results.
Keep tests, examples and documentation in idol. HPC campaign design, submission,
execution, result collection, baselines, analysis and website publication are
strictly outside this backlog and belong to idol-benchmark. Do not wait for
external campaigns or claim HPC validation. Record skipped local tests explicitly.
Do not weaken tests or use heuristic failure as proof of infeasibility.
